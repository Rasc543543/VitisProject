2. ref_rx_packed — Loop_CFO_Scan 問題分析

2.1 程式碼結構

void ref_rx_packed(...)
{
    // ① Load：讀入 2048 點 FFT 資料（20 µs）
Load_Packed:
    for (int i = 0; i < FFT_LENGTH; i++) { ... }

    half max_metric = (half)-1.0f;
    int  best_cfo = 0;           // ← local variable，每次呼叫重置

    // ② CFO Scan：141 × 273 = 38,493 次計算（428 µs）
Loop_CFO_Scan:
    for (int offset = -CFO_RANGE; offset <= CFO_RANGE; offset++)
    {
        ...
        if (metric > max_metric) { best_cfo = offset; }
    }

    int base = LEFT_GUARD + best_cfo;

    // ③ Process：通道估測 + 插值 + ZF 等化（~29~241 µs）
Loop_Process_Packed:
    for (int i = 0; i < PILOT_TONES - 1; i++) { ... }
}

2.2 CFO_Scan 邏輯說明

外層迴圈（141 次）：枚舉所有可能的頻率偏移量 -70 ~ +70

內層迴圈（273 次）：對每個 offset 假設，計算所有 Pilot tone 位置的能量總和
idx = LEFT_GUARD + offset + p * 7（pilot 間距 7 個 subcarrier）

判斷：哪個 offset 下 pilot 能量最大 → 那就是正確的 CFO

核心假設：正確位置的 pilot 能量高，錯誤位置讀到的是 data tone 或 guard，能量相對低。

2.3 問題所在

best_cfo 是 local variable，每幀函數被呼叫時重新初始化為 0，導致：

第 1 幀：初始化 → 掃 141 次 → 找到 best_cfo = +3 第 2 幀：初始化 → 掃 141 次 → 找到 best_cfo = +3 ← 相同答案，浪費 第 3 幀：初始化 → 掃 141 次 → 找到 best_cfo = +3 ← 相同答案，浪費 ...

CFO 是硬體振盪器的頻率差，幀間不變 → 每幀重算是純冗餘。
(Loop_Process_Packed 每幀需要重做，因為通道 H 用當幀實際收到的 pilot 估算，會隨訊號變化。)

2.4 CFO vs 通道估測的差異

CFO（best_cfo）通道估測（H_est）
來源硬體振盪器頻率差實際接收到的 pilot 訊號
幀間是否改變不會（硬體屬性）會（訊號每幀不同）
需要每幀重算？❌ 不需要✅ 必須
作用找 pilot 在哪個 bin（定位）估算通道增益與相位（補償）

3. 優化方案設計

3.1 為什麼不用固定閾值（如 70%）

問題：能量下降有兩種原因
  • ① CFO 漂移 → pilot 跑到錯誤 bin → 需要重掃
  • ② 通道衰減 → 整體訊號變弱 → 不需要重掃，CFO 仍然正確
固定比例無法區分這兩種情況，容易誤觸重掃。

3.2 採用方案：鄰居能量比較（自適應，不需要知道對方硬體規格）

物理直覺：CFO 漂移時，能量從 best_cfo 這個 offset 流向旁邊的 offset。

CFO 正確時：energy(best_cfo-1) < energy(best_cfo) > energy(best_cfo+1) CFO 漂移時：energy(best_cfo+1) > energy(best_cfo) ← 鄰居能量超過自己

通道衰減時：三個 offset 同比例下降，best_cfo 依然最大 → 不誤觸發

3.3 實作程式碼

static int  best_cfo   = 0;
static bool cfo_locked = false;

// Step 1：量測三個 offset 的 pilot 能量（~8 µs，819 次計算）
auto measure_energy = [&](int cfo_offset) {
    half energy = 0;
    for (int p = 0; p < PILOT_TONES; p++) {
        if (p == 136) continue;
        int idx = LEFT_GUARD + cfo_offset + p * 7;
        half vi = fixed16_to_half(buf_i[idx]);
        half vq = fixed16_to_half(buf_q[idx]);
        energy += vi*vi + vq*vq;
    }
    return energy;
};

half e_cur   = measure_energy(best_cfo);
half e_left  = measure_energy(best_cfo - 1);
half e_right = measure_energy(best_cfo + 1);

// Step 2：判斷是否需要重掃
bool need_relock = !cfo_locked || (e_left > e_cur) || (e_right > e_cur);

if (need_relock) {
    // Step 3：完整 141 次掃描（428 µs，只在必要時觸發）
    half max_metric = (half)-1.0f;
Loop_CFO_Scan:
    for (int offset = -CFO_RANGE; offset <= CFO_RANGE; offset++) {
        ...
        if (metric > max_metric) { max_metric = metric; best_cfo = offset; }
    }
    cfo_locked = true;
}

int base = LEFT_GUARD + best_cfo;
// 後續 Loop_Process_Packed 照常執行（每幀用當幀訊號做通道估測）

4. 適用場景說明

場景CFO 穩定性行為
ZCU208 loopback（TX/RX 同一 FPGA）CFO = 0，永遠不變第 1 幀掃描後永遠不重掃
ZCU208 對 USRP（不同硬體）慢漂移（ppm 級）溫度漂移時自動偵測並重掃
ZCU208 對 另一塊 FPGA依振盪器品質同上，品質差則重掃較頻繁
設計優點：不需要知道對方硬體規格。
系統根據實際接收到的 pilot 能量自行判斷是否需要重掃，適用於任何振盪器品質的對端設備。
