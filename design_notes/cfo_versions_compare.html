CFO 是什麼： 發射端與接收端載波頻率不一致，掃描找「哪個 subcarrier offset 讓 pilot 能量最大」。 一旦找到後，在硬體振盪器穩定的情況下這個值幾乎不會改變，重掃是純冗餘計算。

3. 各版本設計說明

原始版本 每幀完整掃描

best_cfo 是 local 變數，每幀重置，無條件跑 141 次。

// local → 每幀歸零
int best_cfo = 0;

for (offset = -70; offset <= 70; offset++) {
    // 273 pilots × 141 = 38,493 次
    energy += vi*vi + vq*vq;
}

代價：每幀 428 µs，無論如何都跑。

版本 A Simple Cache

best_cfo 改 static，只掃一次，永久鎖定。

static int  best_cfo   = 0;
static bool locked     = false;

if (!locked) {
    // 141 次掃描
    locked = true;
}
// 之後完全不掃

問題：Doppler 漂移時 best_cfo 已過期，無法追蹤。

版本 B Neighbor Check

每幀量測 ±1 鄰居，能量漂移才重掃。

if (e_left > e_cur || e_right > e_cur) {
    // 鄰居大 → 觸發完整 141 次重掃
    full_scan();
}

問題：Doppler 每幀都在漂移，每幀都觸發重掃，等同原始版本。

版本 C ★ Tracking Mode

鄰居大 → 直接移過去，不重掃。Doppler 漸進漂移，每幀跟著走。

if (e_left > e_cur && e_left > e_right)
    best_cfo -= 1;    // 往左移一格
else if (e_right > e_cur && e_right > e_left)
    best_cfo += 1;    // 往右移一格
// 永遠只有 3 × 273 次計算

穩定 / Doppler 漂移 → 永遠 ~9 µs。

為什麼 Tracking Mode 對衛星有效？
Doppler 是衛星移動造成的頻率漂移，特性是漸進，不會突然跳變。
LEO 衛星（600 km）：速率 ~200 Hz/s，若 subcarrier 間距 15 kHz，每 75 秒才漂移 1 格。
每幀（~1 ms）最多移 1 格 → Tracking Mode 完全追得上，不需要重掃。

變更 3：能量計算改 SAL（平方 → 絕對值）

ref_rx_packed.cpp — 第 43 行，energy 計算
- p_metric[p & 0x3] += (vi * vi + vq * vq);
+ p_metric[p & 0x3] += (vi < (half)0 ? -vi : vi) + (vq < (half)0 ? -vq : vq);
SAL 為什麼等效： CFO scan 只需要找「哪個 offset 能量最大（argmax）」，不需要精確數值。 L1 norm（|I|+|Q|）和 L2 norm（I²+Q²）對同一組數據的 argmax 結果相同。 改用絕對值可移除 38,493 次浮點乘法，減少 DSP48 使用。
